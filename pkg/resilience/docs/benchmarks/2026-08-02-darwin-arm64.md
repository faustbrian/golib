# Benchmark report: 2026-08-02 Darwin arm64

## Scope

This report compares semantically equivalent synchronous successful function
calls. The direct and no-policy candidates invoke one function and return its
typed value and error. The composed, observed, and budget cases separately
measure behavior that the competitors in the no-policy track do not provide.

## Environment and method

- OS and architecture: Darwin 27.0.0, arm64;
- CPU: Apple M4 Max, 16 logical CPUs;
- Go: 1.26.5;
- owned module: `github.com/faustbrian/golib/pkg/resilience`;
- competitor: `github.com/failsafe-go/failsafe-go` v0.9.6;
- samples: 10 independent Go benchmark samples per case;
- sample duration: 500 ms;
- statistics: `golang.org/x/perf/cmd/benchstat` at
  `v0.0.0-20260709024250-82a0b07e230d`, default non-parametric 95% confidence
  intervals.

Command:

```sh
GOWORK=off go test ./... -run '^$' \
  -bench 'BenchmarkExecutionComposition|BenchmarkBudgetAdmission' \
  -benchmem -benchtime=500ms -count=10
```

## Results

| Case | Median time | Bytes/op | Allocations/op |
| --- | ---: | ---: | ---: |
| Direct function | 3.301 ns | 0 | 0 |
| Failsafe-Go, no policy | 604.9 ns | 288 | 11 |
| resilience, no policy | 473.1 ns | 0 | 0 |
| resilience, two pass-through policies | 247.8 ns | 0 | 0 |
| resilience, bounded observation | 3.940 us | 1.750 KiB | 5 |
| resilience, budget admission and completion | 551.6 ns | 267.0 | 1 |

Other repository verification workloads were active on this development host.
The timing intervals are consequently broad, especially for the short
pass-through cases, and the two-policy median being below the no-policy median
demonstrates that these samples cannot support a speed ranking. The report
supports allocation characterization and records the comparison harness; it
does not establish a universal speed ratio or a regression budget. Release
performance claims require a rerun on an isolated host.
