# Identity Platform Security Event Profile

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
"SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and
"OPTIONAL" in this document are to be interpreted as described in BCP 14
[RFC2119] [RFC8174] when, and only when, they appear in all capitals, as
shown here.

## Ownership and purpose

This profile defines the interoperable security-audit contract for every
identity-platform package. It uses the existing `audit` public contract and the
durable `audit/postgres` adapter selected by `identity/reference`. Audit records
are not application logs, traces, metrics, domain events, or a replacement for
authorization. Logging and telemetry failure MUST NOT weaken an authentication
or authorization decision; audit delivery follows the explicit policy below.

Package goals own when their events occur and the safe domain meaning of those
events. This file owns event names, common fields, outcome semantics, privacy
classification, delivery policy, and cross-package correlation. A worker MUST
NOT invent a synonymous event name or overload an existing name with a
different transition.

## Mapping to `audit` canonical schema version 1

`identity.security.v1` is a profile of the existing `audit` schema, not a new
wire envelope. Packages MUST construct records with `audit.NewBuilder`, persist
them through an `audit.Sink`, and use `audit.CanonicalJSON` and
`audit.ParseCanonicalJSON` as the only canonical codec. The mapping below is
closed; a package MUST NOT invent a second encoding for a profile field.

| Profile value | Exact `audit` representation |
| --- | --- |
| Profile version | `Attributes["identity.profile"] = "identity.security.v1"`; canonical `schema_version` remains integer `1`. |
| Event ID | `Record.ID()`, generated by `Builder.Build` as an opaque random 128-bit-or-stronger ID. |
| Event action | `RecordInput.Action`, observed through `Record.Action()`, using one imperative action name from the taxonomy below, at most 96 ASCII bytes. |
| Times | `RecordInput.OccurredAt` comes from the transition's authoritative UTC clock; `Record.RecordedAt()` is assigned by `Builder.Build` when it constructs the immutable record. |
| Outcome | `RecordInput.Outcome`, observed through `Record.Outcome()`: `audit.OutcomeSucceeded`, `OutcomeDenied`, `OutcomeFailed`, or `OutcomeUnknown`. |
| Reason | `RecordInput.ReasonCode`, observed through `Record.ReasonCode()`, using one code from the catalog below. `RecordInput.Description` MUST be empty. |
| Actor | `RecordInput.Actor`, observed through `Record.Actor()`. During impersonation it is the effective target actor and its single `DelegatedBy` is the initiating actor. Further nesting is forbidden by both this profile and `audit`. |
| Subject | `RecordInput.Subject`, observed through `Record.Subject()`, using a registered subject type and stable internal ID. Unknown-identity operations use the pre-auth transaction/challenge as described below. |
| Tenant | `RecordInput.Context.TenantID`, observed through `Record.Context().TenantID()`. Absence means not tenant-scoped, never global authority. |
| Correlation | `CorrelationID`, `CausationID`, `RequestID`, `TraceID`, and server-side `IdempotencyID` map to `RecordInput.Context` and their `Record.Context()` accessors; the caller's raw idempotency key is forbidden. |
| Producer | `SourceService`, `SourceVersion`, and `Environment` map to `RecordInput.Context` and their `Record.Context()` accessors. |
| Network | `RecordInput.Context.NetworkOrigin` contains only a registered keyed-pseudonym profile plus value; `UserAgent` contains only a registered bounded client class, never raw headers. |
| Authorization | `RecordInput.Policy.PolicyID` and `Version`; `Attributes["authorization.reason"]` contains the safe registered decision reason. |
| Authentication | `RecordInput.Actor.AuthenticationMethod` uses an exported `audit.AuthenticationMethod*` value. `Attributes["authentication.acr"]`, `["authentication.amr"]`, `["authentication.time"]`, `["session.id"]`, and `["session.version"]` carry the bounded optional details. |
| Command | `Attributes["command.id"]`, required for state-changing and reconcilable operations. |
| Scope | Optional canonical IDs use `scope.organization_id`, `scope.team_id`, `scope.client_id`, `scope.provider_id`, `scope.rp_id`, `scope.connection_id`, and `scope.impersonation_grant_id` attribute keys. SCIM Bulk additionally permits `scim.parent_command_id` and unsigned `scim.operation_order`; privacy export permits unsigned `privacy.epoch` and `privacy.watermark_version`. |
| Aggregate | `aggregate.type`, `aggregate.id`, `aggregate.before_version`, and `aggregate.after_version` attributes. |
| Provider | `provider.kind`, `provider.profile`, `provider.version`, and `provider.result` attributes only. |
| Error | `error.code`, containing only a stable owned safe code. |
| Retention | `retention.class`, exactly `standard` or `protected`. |
| Changes | `RecordInput.Changes`, observed through `Record.Changes()`; safe public bounded values MAY use `Before`/`After` with `Redacted=false`. If changed fields cannot be retained, `Redacted=true` and both maps MUST be empty. `NoChange=true` is reserved for an operation that made no structured change and cannot be combined with `Redacted` or either map. |

The implementation MUST expose one typed immutable
`IdentitySecurityEventV1` builder and encode its fields into the string-valued
`Attributes` map only at the `audit` boundary. The encoding is closed:

| Value class | Canonical string encoding |
| --- | --- |
| opaque ID or registered enum | exact registered ASCII token; no normalization |
| authority, aggregate, session, provider, or policy version | unsigned base-10 integer with no sign or leading zero except `0` |
| `authentication.time` | signed base-10 Unix microseconds in PostgreSQL UTC |
| `authentication.amr` | unique registered `audit.AuthenticationMethod*` values sorted by UTF-8 byte order and joined by one ASCII space |
| Boolean | exactly `true` or `false` |
| bounded count | unsigned base-10 integer |

`authentication.acr` is one registered exact profile ID, never a claims map.
The typed builder MUST reject an unknown attribute key, a value of the wrong
class, and an action missing a command, actor, subject, aggregate,
authorization, provider, or retention field required by that action's package
contract. `provider.result` is exactly one of `accepted`, `denied`,
`unavailable`, `timeout`, `throttled`, `malformed`, `ambiguous`,
`binding_mismatch`, or `replayed`; it describes provider evidence, not the audit
commit outcome. `OutcomeUnknown` remains reserved for an unknown state/audit
commit and MUST use `commit_unknown`.

The exact `audit.Limits` profile is `MaxRecordBytes=16384`,
`MaxFieldBytes=256`, `MaxDescriptionBytes=1` (description remains required
empty), `MaxAttributeEntries=32`, `MaxAttributeBytes=8192`,
`MaxChangeEntries=32`, `MaxChangeBytes=8192`, and `MaxIntegrityBytes=32`.

All attribute keys above are reserved. Optional values MUST be absent rather
than empty. No record has more than 32 attributes, every string is at most 256
UTF-8 bytes, and canonical JSON is at most 16 KiB. Builders MUST configure
`audit.Limits` accordingly, which is stricter than the primitive ceiling.
Unknown profile attribute keys and reuse of a key with a different type or
meaning MUST be rejected before record construction.

IDs use the repository identifier primitive's canonical text form, are at most
64 ASCII bytes, and MUST NOT be credentials, provider subjects, emails, phone
numbers, usernames, or caller-supplied idempotency keys. Registered codes and
names match `[a-z][a-z0-9_]*(\.[a-z0-9_]+)*`. Free-form reasons, display names,
provider messages, and raw claims are forbidden.

For an enumeration-safe operation where no identity/resource is known,
`Subject.Type` is `authentication_attempt` and `Subject.ID` is the opaque random
pre-auth transaction or challenge ID. It MUST NOT be an identifier, an
identifier digest, or a fabricated user ID. An anonymous actor uses
`audit.ActorAnonymous` with no actor ID; the operation subject still supplies
the required attempt ID.

`OutcomeUnknown` means the transition may have committed but current evidence
cannot distinguish it. It MUST NOT be rewritten. Reconciliation emits a new
correlated record. Each required action emits exactly one record with one
outcome. One composed command MAY emit multiple non-synonymous required
actions; they share command and correlation IDs and use distinct causation IDs.
Administrator context is represented by Actor/DelegatedBy and Policy, never by
a second synonymous administrator event.

## Stable event taxonomy

The following names are reserved and exhaustive for the selected end state.
An implementation MAY omit events for an unsupported operation, but every
implemented operation MUST use its exact event action. Actions name the
operation in imperative form; success, denial, failure, or uncertainty belongs
only in `Record.Outcome()`. A worker MUST NOT append `_succeeded`, `_denied`,
`_failed`, `_expired`, or another result to create a new action.

The table is also the complete baseline retention mapping. Every listed action
MUST set the row's `retention.class`, except that an event for an operation
authorized by a privileged administration statement MUST set `protected` even

Expiration is an outcome only when an operation encounters expired material.
Scheduled lifecycle expiry uses its owning imperative operation, such as
`identity.session.expire`, `identity.anonymous.expire`, or
`identity.risk.end_lockout`, with `OutcomeSucceeded` and reason `completed`.
Administrator password reset, session revocation, and factor reset use the same
password/session/MFA actions as self-service; Actor/DelegatedBy, Policy, and
scope identify the privileged initiator without a synonymous admin action.

Anonymous upgrade MUST emit `identity.anonymous.upgrade` and
`identity.session.rotate` under the same command/correlation IDs. The upgrade
event names the anonymous subject and permanent target only through their
opaque aggregate IDs; the rotation event names the old session family/version
and new session version. No event may contain the anonymous bearer, merge
payload, verified credential, or transferred application data. The upgrade
MUST NOT report `OutcomeSucceeded` unless revocation of the old anonymous
session family and issuance of the permanent session committed atomically.

A privacy-export request, completion, cancellation, and download MUST include
the export ID as aggregate ID plus safe unsigned `privacy.epoch` and
`privacy.watermark_version` attributes registered by the identity package.
Completion is successful only after every required contributor checkpoint and
artifact digest is committed; it MUST NOT include exported fields, fragment
digests, download capability material, object-store location, or legal-hold
detail. A deletion/anonymization race that cancels an export emits the normal
cancel action with the destructive command as causation; artifact erasure does
not create a second successful completion event.

Each SCIM Bulk request MUST emit one `identity.scim.bulk_admit` event for the
parent command. Every child that enters `in-progress` MUST emit exactly one
`identity.scim.bulk_apply_child` event with that child command's outcome. Every
child durably changed from `not-started` or `blocked-unknown-dependency` to
`skipped-fail-on-errors` MUST emit `identity.scim.bulk_skip_child` with
`OutcomeDenied` and registered reason `identity.scim.fail_on_errors_cutoff`.
Bulk events MAY contain only the parent command ID, child command ID, unsigned
operation order, and scoped connection ID; raw or digested `bulkId`, method
path, resource body, attribute values, dependency IDs, and response detail are
forbidden. Reconciliation uses
`identity.scim.reconcile` with the original parent/child command as causation
and MUST NOT rewrite the original event.

## Stable reason-code catalog

`Record.ReasonCode()` MUST be exactly one of these common codes unless a package
goal registers a namespaced extension:

- `completed`
- `invalid_input`
- `not_authenticated`
- `not_authorized`
- `not_found_hidden`
- `conflict`
- `expired`
- `replayed`
- `rate_limited`
- `risk_denied`
- `step_up_required`
- `provider_denied`
- `provider_unavailable`
- `timeout`
- `cancelled`
- `commit_unknown`

An extension MUST match `identity.<owning_package>.<code>`, be declared in that
package goal before assignment, be enumeration-safe, and MUST NOT duplicate a
common code. `completed` is required for a successful operation without a more
specific registered reason. `OutcomeDenied` uses policy/caller-caused codes;
`OutcomeFailed` uses operational failure codes; `OutcomeUnknown` uses only
`commit_unknown`. A code MUST NOT leak identifier existence, provider text,
policy internals, or credential material.

## Actor, subject, and authorization invariants

For an impersonated operation, `Record.Actor()` is the effective target actor and
its one `DelegatedBy` is the initiating actor. The impersonation grant ID uses
the registered `scope.impersonation_grant_id` attribute; a second delegation
level is forbidden. A system reconciliation uses `audit.ActorSystem`,
identifies the owning worker through a bounded actor ID, and links to the
original command through `Record.Context().CausationID()`.

Privileged operations MUST record the named authorization statement, policy
version, and decision. Authentication success is not an authorization reason.
Denials MUST be externally enumeration-safe while the audit `reason_code`
retains only a safe classification. A record MUST NOT include raw role or claim
maps; it may include registered role/statement IDs and versions.

The audit privacy policy MUST be implemented with `audit.RedactionRules` (or an
equivalent `audit.Redactor`) before persistence. Attribute and change
allowlists contain only profile-registered safe keys. Redaction cannot replace
a sensitive value with the word `redacted`: when every structured change is
removed, the `audit` contract represents that state as empty `Before`/`After`
maps with `Record.Changes().Redacted()` true.

## Atomicity, delivery, and reconciliation

State change and its required audit record MUST share a caller-owned database
transaction when the state and `audit/postgres` are in the same PostgreSQL
boundary. Otherwise the state transaction MUST write a durable outbox record
with the canonical audit event. The dispatcher MUST preserve event ID,
canonical bytes, causation, and idempotency. Duplicate delivery of identical
canonical bytes is idempotent; reuse of an event ID with different bytes is an
integrity failure.

The reference policy is:

- privileged administration, impersonation approval/start, credential or
  factor reset, organization ownership/role changes, SSO/SCIM configuration,
  OAuth client/key changes, and audit-retention/legal-hold changes MUST fail
  closed unless their audit event is atomically committed or durably buffered;
- a denial MUST remain denied if audit storage is unavailable; its missing
  record MUST raise a bounded operational alert and reconciliation item;
- successful authentication and ordinary user self-service changes require
  atomic or durable-buffer delivery and MUST NOT be reported as successful on
  an unknown state/audit commit; and
- logs, metrics, traces, and exporters MUST NOT substitute for required audit
  delivery.

Every unknown result MUST create or preserve a reconciliation item keyed by
`command_id`. Reconciliation emits a new event with its own ID and the original
event or command as `causation_id`; it never edits an immutable prior record.

## Privacy, integrity, and operations

Passwords, OTP/TOTP/recovery codes, WebAuthn challenges or raw ceremony data,
cookies, bearer/API keys, OAuth/SAML/SCIM tokens, authorization codes, provider
responses, client secrets, cryptographic private material, email/SMS bodies,
raw IP addresses, raw user agents, raw claims, and unbounded user text MUST NOT
appear in an event.

This includes CAPTCHA response tokens, remote IP, `cdata`, raw
hostname/action/site values; HIBP SHA-1 prefixes/suffixes, range bodies and
cache keys; keyed digest bytes and secret key versions usable as correlators;
delivery recipients, rendered variables/bodies, links and provider receipts;
and PostgreSQL/Valkey DSNs, endpoints, credentials, commands, or keys. Permitted
provider data is limited to the registered bounded provider kind/profile/version
and `provider.result`; permitted subject/network correlation uses only the
registered keyed-pseudonym profile and its scoped rotating opaque value. A
configuration value classified secret by `REFERENCE_CONFIGURATION.md` is
unconditionally prohibited even when a caller labels it safe.

`audit.retention.standard` (365 days) and `audit.retention.protected` (400 days)
from `REFERENCE_CONFIGURATION.md` are bootstrap defaults only. The
`audit/postgres` durable runtime retention policy is the sole runtime authority:
it is initialized exactly once from those defaults, versioned thereafter, and
read on every restart. A restart MUST NOT overwrite it, and configuration drift
MUST NOT mutate it. `identity.audit-retention.policy.update` is the only online
mutation and emits `identity.audit_retention.change_policy`; unset and reset are
unsupported, so returning to an earlier duration is another explicit versioned
update rather than deletion of policy state. The version-1 initialization emits
exactly `identity.audit_retention.change_policy` with the system bootstrap actor,
the selected defaults, and initialization reason in the same transaction as the
durable policy row; losing that event makes initialization fail closed.
Lifecycle-envelope retention is separately controlled by `lifecycle.*` rows.
A legal hold is a separately
authorized audited state and suspends deletion only for its declared scope.
Exports MUST preserve canonical bytes, chain/checkpoint evidence, schema and
redaction policy. Retention deletion MUST itself be bounded, attributable, and
audited without recursively generating one event per deleted record.

`audit/postgres` MUST be mandatory for production readiness. Integrity sealing,
checkpoint verification, backup/restore, retention, legal hold, partition
isolation, query authorization, exporter outage, and tamper detection MUST be
exercised in the final reference profile. An in-memory sink, log sink, trace
exporter, or best-effort callback is not completion evidence.
